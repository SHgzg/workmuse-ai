# ADR 0001：首期业务对象使用版本化本地存储

## 状态

已采用（首期实现）。

## 背景

目标、任务和成果需要先形成可运行的本地闭环，同时项目坚持本地优先、Renderer 无高权限能力，并要求应用更新前可备份用户数据。目前项目没有已选定的数据库生产依赖。

## 决策

首期在主进程使用版本化 JSON 快照保存业务对象，位置为 `userData/database`。通过类型化 preload API 暴露最小的列表、创建和状态更新操作；输入在主进程存储层验证。写入使用串行队列和原子替换。

## 影响

- 无需引入新的生产依赖即可实现离线持久化和升级备份。
- 数据格式带版本，后续迁移到 SQLite 或服务端时可显式迁移与回滚。
- 该方案不适合作为多人并发数据库；引入团队同步、复杂查询或大量审计记录前需要替换存储实现，但 Renderer API 可保持稳定。
