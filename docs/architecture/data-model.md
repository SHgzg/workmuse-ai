# 本地业务数据模型

## 当前范围

当前业务存储覆盖项目、会议、灵感、目标、任务、成果和已确认知识，文件位于 Electron `userData/database/workspace.v1.json`。Renderer 只能通过 preload 暴露的受控接口读写，不能直接访问文件系统。

所有实体具有稳定 ID、创建/更新时间、说明和来源列表。来源类型包括用户手动创建、原始资料、会议、灵感和 AI 建议；没有外部依据的手动输入明确记录为“用户手动创建”，不伪装成原始事实。

## 关系

- 任务可以关联一个目标，并分别保存预期成果和验收标准。
- 任务可以关联一个项目；项目聚合任务和会议。
- 会议可以关联项目、多个目标及已导入资料。资料只保存 checksum 资源 ID，主进程在写入前验证原文件存在于受控 AssetStore。
- 会议可在计划中、进行中、已结束和已取消之间流转；上传录音或材料时先完成 AssetStore 导入与 Core 处理，再以幂等方式追加资源关系。
- 成果可以关联一个目标和一个任务。
- 灵感可原子地转为任务；任务来源保存灵感 ID，重复点击转换不会创建重复任务。
- AI 问答可转为任务；任务同时保存 `ai-suggestion` 来源以及参与回答的原始资料 ID 和证据块 ID。AI 文字仍是推断，原始材料引用单独保留。
- 资料语义结果中的行动项必须经用户确认才创建任务；任务保存对应资源与证据块，UI 明确将其标记为 AI 提取结果。
- Core 提取的观点默认为待确认信息；只有至少包含一个原始资源与证据块的观点才能由用户确认入库。相同证据块重复确认返回已有知识。
- 完成任务只改变任务状态，不会自动创建成果或更新目标值。
- 成果按草稿、待审核、已确认、已拒绝流转；只有显式审核操作改变状态，任务完成不会自动确认成果。
- 目标当前值由用户显式更新。差距按“目标值 − 当前值”展示；缺少任一数值时显示数据不足，并单独展示可计算的指标完成度与时间进度依据。
- 引用不存在的目标或任务时拒绝写入。

## 持久化与兼容

- 顶层 `schemaVersion` 当前为 `4`；旧版本会补齐灵感、项目、会议、任务项目关系与知识列表后迁移到版本 4，未知版本拒绝加载，避免静默破坏数据。
- 写入在主进程内串行执行，并通过同目录临时文件和原子替换落盘。
- 只有落盘成功后才更新内存快照；一次写入失败不会污染后续写入队列。
- 数据库目录包含在应用更新前的本地备份中。

## 当前限制

成员权限、审计日志、会议转录流程、成果审核操作和多工作区隔离尚未加入该存储。进入团队协作前必须先确定权限模型与迁移方案。
